# Compra em Casa — especificação completa para recriação no Replit

## 1. Objetivo

Criar um aplicativo mobile-first, em português do Brasil, para controlar as compras da casa.

O usuário cadastra previamente os itens que costuma comprar. Durante a compra, marca os itens como comprados. O aplicativo deve funcionar em mais de um celular usando uma mesma “casa” compartilhada. Exemplo: uma pessoa cria a casa e a outra entra com o código da casa.

O aplicativo também deve receber o endereço do QR Code da nota fiscal, consultar a página fiscal, importar mercado, data, total e produtos/preços quando disponíveis, e registrar essas informações no histórico.

Não criar:

- sistema de múltiplas listas;
- configuração de itens recorrentes;
- inclusão de item por voz;
- leitura de código de barras de produtos;
- login complexo ou senha obrigatória.

## 2. Nome e identidade

- Nome: Compra em Casa
- Idioma: pt-BR
- Tipo: PWA responsivo, prioritariamente para celular
- Tela principal: área de trabalho do app, não uma landing page
- Fonte do corpo: DM Sans
- Fonte dos títulos: Fraunces
- Paleta atual:
  - tinta principal: #17251f
  - fundo: #f7f8f2
  - superfície: #ffffff
  - borda: #e1e7de
  - verde-limão: #d7f25e
  - coral: #ed674d
  - verde suave: #e8f4e8
  - azul suave: #e7f0f5
- Layout centralizado, largura máxima aproximada de 560px, com navegação inferior no celular.
- Usar cartões arredondados, botões grandes para toque, boa leitura e estados vazios/erro/sucesso.
- Usar emojis nos itens; não é necessário incluir imagens de produtos.

## 3. Tela principal: Comprar

Cabeçalho:

- marca “Compra em Casa”;
- subtítulo pequeno “lista compartilhada”;
- botão de conexão da casa, inicialmente “Conectar”, depois mostrando o código da casa;
- botão de sincronização manual.

Quando ainda não há casa conectada, mostrar o banner:

- título: “Compartilhe esta casa”;
- texto: “Crie um código para usar a mesma lista em dois celulares.”;
- botão: “Configurar”.

Conteúdo principal:

- data atual em português;
- título: “O que falta em casa?”;
- cartão de progresso da compra:
  - “compra atual”;
  - quantidade no formato “0 de 19 itens”;
  - porcentagem;
  - barra de progresso;
  - texto de itens restantes;
  - botão “Limpar comprados”, visível somente quando houver comprados;
  - botão “Nova compra”.

Ações rápidas:

- “Ler nota fiscal” / “Atualizar preços pelo QR Code”;
- “Ver histórico” / “Quando cada item foi comprado”.

Lista:

- título “Lista de compras”;
- botão “＋ adicionar”;
- filtros:
  - “Tudo”;
  - “Falta comprar”;
  - “Comprados”.
- agrupar itens por categoria;
- cada item deve mostrar emoji, nome, status, quantidade, unidade, observação e controles de quantidade;
- botão para marcar/desmarcar como comprado;
- botão para editar o item.

Ao marcar um item como comprado:

- o item fica visualmente riscado/desativado;
- registra data/hora da compra;
- cria uma entrada no histórico com fonte “lista”;
- a alteração deve sincronizar com os celulares conectados.

Ao desmarcar, retirar o status de comprado, mas não apagar o histórico já registrado.

“Limpar comprados” remove os itens comprados da lista atual, mas preserva todo o histórico.

“Nova compra” recria a lista usando todos os itens cadastrados, com suas quantidades padrão e status aberto.

## 4. Tela: Meus itens

Cabeçalho:

- subtítulo “seu repertório”;
- título “Meus itens”;
- texto: “Cadastre o que vocês compram sempre e coloque na lista quando precisar.”;
- campo de busca “Buscar item cadastrado”.

Listar os itens agrupados por categoria.

Cada item deve permitir:

- adicionar/remover da lista atual;
- editar;
- excluir.

Ao criar um item novo:

- cadastrar no catálogo;
- colocar automaticamente o item na lista atual;
- usar a quantidade padrão informada.

Ao editar um item:

- atualizar nome, categoria, quantidade padrão, unidade, observação e emoji;
- se o item estiver na lista e ainda não estiver comprado, atualizar também a quantidade da lista.

Não permitir itens duplicados ignorando maiúsculas/minúsculas e acentos.

## 5. Tela: Histórico

Cabeçalho:

- subtítulo “memória da casa”;
- título “Histórico”;
- cartão “registros”;
- cartão “última compra”.

Listar registros do mais recente para o mais antigo, agrupados por data.

Cada registro deve mostrar:

- emoji;
- nome do item ou produto;
- supermercado, quando conhecido;
- preço, quando conhecido;
- quantidade e unidade.

Se não houver histórico, mostrar:

“Quando vocês marcarem um item como comprado ou importarem uma nota fiscal, o registro aparecerá aqui.”

## 6. Navegação inferior

Três abas:

- Comprar;
- Meus itens;
- Histórico.

Manter a aba atual destacada.

## 7. Modal de casa compartilhada

Título: “A mesma lista em dois celulares”.

Texto: “Crie uma casa no primeiro celular. No segundo, entre usando o mesmo código.”

Controles:

- botão “Criar uma casa”;
- campo “Código recebido”, placeholder “CASA-AB12”;
- botão “Entrar”.

Depois de criar uma casa:

- gerar código no formato `CASA-XXXX`;
- exibir cartão “código desta casa”;
- permitir “Copiar código”;
- manter a lista e o catálogo já existentes;
- mostrar o código no cabeçalho.

Ao entrar:

- carregar catálogo, lista, histórico e notas fiscais da casa;
- salvar o código no dispositivo;
- marcar a conexão como ativa.

Se o usuário tentar importar uma nota sem casa conectada:

- guardar temporariamente o endereço informado;
- fechar o modal da nota;
- abrir o modal da casa;
- mostrar: “Para importar esta nota e compartilhar os preços, primeiro crie uma casa ou entre com um código. O endereço da nota ficará guardado.”;
- depois da conexão, reabrir o modal da nota com o endereço preenchido.

## 8. Modal de nota fiscal / QR Code

Título: “Atualizar preços pelo QR Code”.

Texto: “Aponte a câmera para o QR Code da nota. O app tentará importar produtos, preços, mercado, data e total.”

Funcionalidades:

1. Botão “Abrir câmera”.
2. Usar `BarcodeDetector` quando o navegador oferecer suporte.
3. Solicitar câmera traseira (`facingMode: environment`) em contexto seguro HTTPS.
4. Mostrar área de câmera e moldura para QR Code.
5. Ao ler o QR Code, preencher o campo e permitir conferência antes do envio.
6. Se o navegador não suportar leitura automática, mostrar instrução para colar o endereço.
7. Campo “Endereço da nota”, placeholder “https://...” ou URL `http://`.
8. Botão “Importar nota fiscal”.
9. Botão “Parar câmera”.

Ao importar:

- enviar o endereço ao servidor;
- consultar a página fiscal;
- tentar identificar supermercado, data, total e produtos/preços;
- salvar a nota mesmo que a leitura detalhada falhe;
- mostrar resultado de sucesso, parcial ou erro;
- atualizar histórico e preços sem apagar dados anteriores.

QR Codes oficiais podem usar HTTP ou HTTPS. Aceitar os dois protocolos, com validação de domínio fiscal para evitar consultar endereços arbitrários.

O parser atual usa heurísticas:

- nome do mercado pelo `og:site_name` ou `<title>`;
- total por expressões como “valor total”, “total a pagar”, “total da nota” e “valor a pagar”;
- data no formato `dd/mm/aaaa` ou equivalente;
- produtos/preços por JSON-LD `application/ld+json`;
- máximo de 200 itens extraídos.

Importante: páginas de SEFAZ podem mudar de formato ou bloquear robôs. O sistema deve guardar o QR Code e informar quando os dados detalhados não puderem ser lidos.

## 10. Persistência e modo offline

O servidor/banco é a fonte de verdade quando a casa está conectada.

No dispositivo, usar armazenamento local somente para:

- rascunho e fallback local;
- catálogo/lista temporários quando o servidor estiver indisponível;
- código da casa já utilizado;
- preferências e cache PWA.

Chave atual do estado local: `compra-em-casa-v2`.

Chave atual do código da casa: `compra-em-casa-house`.

Se uma alteração for feita sem conexão:

- manter a alteração visível neste celular;
- informar “Alteração salva neste celular; sincronização pendente.”;
- tentar sincronizar novamente quando a conexão voltar.

## 11. Modelo de banco de dados

Usar SQLite/D1, PostgreSQL ou equivalente persistente. Não usar somente localStorage.

### households

- `id TEXT PRIMARY KEY`
- `code TEXT UNIQUE NOT NULL`
- `created_at TEXT NOT NULL`

### catalog_items

- `id TEXT PRIMARY KEY`
- `household_id TEXT NOT NULL`
- `name TEXT NOT NULL`
- `category TEXT NOT NULL`
- `emoji TEXT NOT NULL`
- `default_qty INTEGER NOT NULL DEFAULT 1`
- `unit TEXT NOT NULL DEFAULT 'un'`
- `note TEXT NOT NULL DEFAULT ''`
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`
- relação com households com exclusão em cascata

### shopping_items

- `id TEXT PRIMARY KEY`
- `household_id TEXT NOT NULL`
- `catalog_id TEXT NOT NULL`
- `quantity INTEGER NOT NULL DEFAULT 1`
- `bought INTEGER NOT NULL DEFAULT 0`
- `bought_at TEXT NULL`
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`
- unicidade por `(household_id, catalog_id)`

### purchase_history

- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `household_id TEXT NOT NULL`
- `item_name TEXT NOT NULL`
- `emoji TEXT NOT NULL DEFAULT '🛒'`
- `purchased_at TEXT NOT NULL`
- `price_cents INTEGER NULL`
- `quantity REAL NOT NULL DEFAULT 1`
- `unit TEXT NULL`
- `supermarket TEXT NULL`
- `source TEXT NOT NULL` — valores esperados: `lista` ou `nota_fiscal`
- `receipt_id TEXT NULL`

### receipts

- `id TEXT PRIMARY KEY`
- `household_id TEXT NOT NULL`
- `qr_url TEXT NOT NULL`
- `supermarket TEXT NULL`
- `issued_at TEXT NULL`
- `total_cents INTEGER NULL`
- `imported_at TEXT NOT NULL`
- `resolved INTEGER NOT NULL DEFAULT 0`

Criar índices por casa, status de comprado e data.

## 12. API necessária

Todas as requisições da casa usam o header:

`X-House-Code: CASA-XXXX`

Formato JSON e CORS para o domínio do app.

### Criar casa

`POST /api/households`

Recebe catálogo/lista local opcional e devolve o estado completo da casa, incluindo o código criado.

### Entrar em casa

`POST /api/households/join`

Body: `{ "code": "CASA-AB12" }`

Devolve o estado completo ou erro 404 “Casa não encontrada.”

### Consultar casa

`GET /api/households/:code`

Devolve:

```json
{
  "code": "CASA-AB12",
  "catalog": [],
  "list": [],
  "history": [],
  "receipts": []
}
```

### Catálogo

- `POST /api/items` — cria item e o coloca na lista;
- `PUT /api/items/:id` — edita item;
- `DELETE /api/items/:id` — exclui item e sua entrada da lista.

### Lista

- `POST /api/list/items` — adiciona item existente;
- `PUT /api/list/items/:id` — altera quantidade/status; ao marcar como comprado, cria histórico;
- `DELETE /api/list/items/:id` — remove item da lista;
- `POST /api/list/clear-bought` — remove itens comprados da lista;
- `POST /api/list/reset` — recria a lista com todos os itens do catálogo.

### Nota fiscal

`POST /api/receipts/resolve`

Body:

```json
{ "qrUrl": "http://nfce.sefaz..." }
```

O servidor deve consultar a URL fiscal, salvar a nota, salvar os produtos detectados no histórico e devolver:

```json
{
  "receipt": {
    "id": "...",
    "qrUrl": "...",
    "supermarket": "...",
    "issuedAt": "2026-09-13",
    "totalCents": 12590,
    "importedAt": "...",
    "resolved": true
  },
  "message": "...",
  "state": {}
}
```

Se a consulta fiscal falhar, retornar `resolved: false`, salvar o QR Code e informar o motivo sem apagar o registro.

## 14. PWA e instalação

Incluir:

- `manifest.webmanifest` com nome “Compra em Casa”;
- `display: standalone`;
- `lang: pt-BR`;
- ícone SVG/fav icon;
- service worker para cache básico offline;
- atualização de versão do cache quando os arquivos mudarem.

No celular, o usuário deve conseguir abrir o link HTTPS e usar “Adicionar à tela inicial”.

## 15. Publicação no Replit

Publicar com HTTPS e banco persistente.

Requisitos:

- não entregar somente um arquivo HTML local;
- hospedar o front-end e a API;
- configurar o banco persistente;
- executar a migração do banco;
- permitir que dois celulares abram o mesmo endereço;
- usar o código da casa para separar os dados entre famílias;
- não colocar tokens ou segredos no código do navegador;
- confirmar que a API está funcionando antes de entregar o link.

O Site atual usa um Worker Cloudflare com binding D1 chamado `DB`. No Replit, pode-se substituir por PostgreSQL/SQLite persistente, desde que o comportamento e o modelo de dados sejam preservados.

## 16. Critérios de aceite

1. Abrir o app no celular sem layout quebrado.
2. Criar casa e gerar código.
3. Abrir outro celular, informar o código e ver a mesma lista.
4. Marcar item como comprado em um celular e vê-lo atualizado no outro.
5. Criar, editar, excluir e pesquisar itens.
6. Limpar comprados sem apagar histórico.
7. Criar nova compra com todos os itens cadastrados.
8. Ler QR Code pela câmera quando o navegador suportar.
9. Colar URL HTTP ou HTTPS da nota.
10. Salvar mercado, data, total, QR Code e produtos identificados.
11. Mostrar falha parcial sem perder a nota cadastrada.
12. Ver histórico por data, item, mercado e preço.
13. Funcionar como PWA instalável.
14. Manter os dados no servidor, não somente no navegador.

## 17. Observação sobre a versão atual

Esta especificação reproduz a versão atual do projeto “Compra em Casa”. A versão local está funcional e validada. A publicação online ainda não foi concluída porque o ambiente de desenvolvimento atingiu o limite de uso antes de enviar o código ao servidor.
